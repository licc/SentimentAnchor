# 更新记录

## 2026-10-25 · 局域网访问与 OCR 识别修复

### 前端

- **SSE 断线自建重连**。`EventSource` 只在"网络层断开"时自动重连；若服务端（或开发代理）返回的是
  一个合法的 HTTP 非 200（例如后端重启瞬间代理报 `502`/`ECONNREFUSED`），按规范客户端会**永久放弃**，
  页面从此收不到快照、停在旧数据上。现在改为 `onerror` 里主动 `close()` 并重建连接，
  退避 2s → 4s → 8s → 16s（上限 30s）。
- **倒计时改为纯本地计时**。原实现是 `nextRefreshAt − 客户端本地时钟`，远程设备（手机/另一台电脑）
  时钟只要偏差几秒，倒计时就恒为 0，顶部环形进度条看起来"不转"，误以为没有刷新。
  现以"收到上一帧的本地时刻"为基准推算，与设备时钟无关。
- **兜底轮询收紧**。连续 12 秒（原 22 秒）收不到推流时自动改走 `GET /api/snapshot`，即使 SSE 被中间层掐断，
  数据也不会僵住。
- **局域网可访问**。`vite` 监听改为 `0.0.0.0`；`server.watch` 排除 `thsapi/`（其 `.venv` 含上万个文件，
  纳入监听会拖垮 dev server）。

### 后端

- `GET /api/health` 新增 `sseClients` 字段（当前挂着 `/api/stream` 的浏览器数量），
  `/api/stream` 增加接入/断开日志。排查"远程页面不刷新"时先看这两个信号：
  `sseClients` 为 0 说明页面根本没订阅上，而不是数据没变。
- `HOST` 支持 `0.0.0.0`；非回环且未设置 `APP_TOKEN` 时会打印安全提示（原有逻辑，本次确认可用）。

### thsapi 适配器（同花顺 GUI 通道）

- **新增 RapidOCR 主引擎**：`thsapi/gui/ocr_rapid.py`，使用 RapidOCR（PaddleOCR 的 ONNX 离线版，
  模型随 pip 包分发，不联网）。持仓表实际只有 12px 字高，Windows 自带 OCR 在这个尺度下会把
  「黄金ETF」认成 `E±ETF`/`黄±ETF`、把 `518880` 认成 `S18880`，`×`/`±`/`亻` 混淆严重。
  系统 OCR 保留为兜底（未安装 RapidOCR 时自动回退）。
- **引擎可切换**：环境变量 `THSAPI_OCR_ENGINE=rapid|windows|auto`（默认 `auto`）。
- **价格小数点误识修复**：OCR 常把 `8.199` 读成 `8,199`，而原解析把逗号当千分位删掉，导致市价放大 1000 倍、
  盈亏算成天文数字。现在价格单元格出现"只有逗号没有点"时按小数点处理，并用
  「市值 ÷ 持股数」交叉校验，明显不一致时以校验值为准，随后重算盈亏与盈亏比。
- **按列校验 + 定点补读**：证券代码校验为 6 位数字、证券名称校验是否含可疑字符，
  只对可疑单元格二值化后按多组放大倍数重新识别（正常表格零额外开销）。
  补读放在"表格疑似残缺重拍"之后，避免重拍整表覆盖修复结果。
- **JSON 响应补 `charset=utf-8`**：`application/json` 不带 charset 时，部分客户端（如 Windows PowerShell 5.1）
  会按 Latin-1 解码，把 `黄金ETF` 显示成 `é»éETF` —— 这是客户端解码假象，现在服务端显式声明编码。
- **测试**：新增 2 个回归用例（OCR 小数丢失修复、名称乱码判定），`pytest` 从 20 → **22 passed**。

### 升级注意

- 已部署的环境需要补装依赖：`python -m pip install -r requirements.txt`（新增的 OCR 依赖约 75MB）。
  不装也能启动，会自动回退到系统 OCR，只是名称/价格容易被认错。
- 新增依赖为纯离线包，不影响"整套东西只依赖本机交易客户端、不需要外网"的设计。
