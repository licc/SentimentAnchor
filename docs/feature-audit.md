# 功能有效性审计

原则：**每个可见入口都必须回答一个真实问题，或触发一个真实动作。** 不做“看起来有”的按钮，不用写死数据撑功能。

## 一、保留并明确用途

| 功能 | 回答的问题 | 真实动作 / 数据 |
| --- | --- | --- |
| 指数条 | 今天指数强不强？ | 6 个指数实时 OHLC/成交额 |
| 情绪定调 | 今天能不能做？ | 广度、涨跌停、量能、阶段、风险 |
| 9 个锚点 | 今天看哪几只？ | 从涨停/跌停池与榜单动态选股 |
| AI 研判 | 结论是什么？风险在哪？ | 本地量化推理；可选 LLM |
| T+0 ETF 情绪套利台 | 情绪变化如何映射到 ETF？ | 顶部独立 `/etf`、系统每日选池、30%–70% 分级仓位、14:55 清仓、每日记录 |
| 交易事件 | 过去为什么做这个决策？ | 最右侧共用时间线，按时间倒序记录情绪、广度、目标、账户、持仓和报价 |
| ETF 执行审计 | 每次下单是否真的执行？失败怎么办？ | 因子、合同编号、回执、成交核对、撤单/暂停/人工处理 |
| T+0 选池 | 开盘前缓存会在 09:30 后强制重选一次；候选显式标记 T+0 |
| 系统选池 | 今天做哪只 ETF？ | 20 日波动 + 成交额 + tick 成本 + 当日相对强弱，每日更新 |
| ETF 手续费 | 1 万账户来回成本是多少？ | 佣金万2最低5、无印花税、往返成本估算、日 0.3% 上限 |
| 周期日志 | 为什么是这个判断？ | 5 个规则模块，数据可追溯 |
| 辨识度双榜 | 谁在赚钱/亏钱？ | 涨停梯队 + 跌幅榜 |
| 周期规则 | 什么情况确认/失效？ | 3 组可打勾条件 |
| 周期日历 | 今天处在什么周期位置？ | 14 日历史涨停池 + 阶段统计 |
| 预警中心 | 什么时候需要提醒我？ | 规则、冷却、浏览器通知、Webhook |
| 自选池 | 我真正盯的票呢？ | 6 位代码增删、纳入刷新 |
| 数据源 | 现在数据可信吗？ | 源状态、延迟、降级提示 |
| 决策台/全量监控 | 现在该看什么？ | 默认聚焦，深度图表按需展开 |
| 摸鱼页 | 不被一眼看出是行情软件 | `/docs` 周报伪装 + 快捷键切换 |
| 无操作自动阅读 | 离开电脑自动伪装 | 40s 无操作进入 `/docs`，工具菜单可关闭 |
| 正式页深色 | 夜间/低光环境下不刺眼 | 炭黑 + 涨墨色/跌灰色 + 细节低饱和红绿，跟随系统并持久化 |
| 涨跌墨色 | 暗色避免满屏红绿，亮色保留习惯 | 亮色保持红绿；暗色涨近白、跌灰色 |
| 阅读页结构 | 切换后不像另一套产品 | 复用正式页顶部栏/工具栏/编号卡片/右侧信息栏 |
| 摸鱼暗色 | 在暗色 IDE/夜间环境中不突兀 | 周报页主题切换，持久化并跟随系统 |
| 工具菜单 | 高级操作在哪？ | 模拟/导入/导出/数据源收拢，不挤占主操作 |

## 二、合并 / 删除的内容

| 内容 | 处理 | 原因 |
| --- | --- | --- |
| 顶部导入/导出/数据源/模拟 4 个独立按钮 | 收进“工具”菜单 | 降低顶部噪声，移动端也能完整访问 |
| `/api/note` 与 `note` 配置 | 删除 | 没有前端入口，属于死接口 |
| `up5/down5`、`limitUpPremium`、`isDemo` | 删除 | 未展示、未参与决策，避免误导 |
| 离线种子快照 | 删除 | 会变成写死股票，违反真实数据原则 |
| 固定“常用股票” | 删除 | 自选快捷项改为当前锚点动态生成 |
| 默认页面直接展示情绪曲线+日历 | 收进全量监控 | 决策台先给结论，深度分析按需查看 |
| 股票模拟交易 | 删除 | 工具菜单纸交易账户，避免与实盘/ETF模拟混淆 |

## 三、保留但明确边界

| 功能 | 边界 |
| --- | --- |
| AI 本地推理 | 是规则合成，不是大模型；页面明确标注 |
| AI Key 配置 | 界面可配置，服务端文件 0600，接口只回掩码；环境变量优先 |
| 模型发现 | 调服务商 `/models` 自动列出可用模型；DeepSeek 实测返回 `deepseek-flash` / `deepseek-v4-pro` |
| AI LLM | 需要 Key；输出可能出错，未做统计校准 |
| 周期日历 | 14 日小样本；阶段按涨停池近似，不含全市场广度 |
| 阶段回测 | 仅“阶段 → 次日上证”，不是完整策略回测 |
| 接口故障 | 偶发超时/断线不停止；waiting/recovering 退避重试；人工暂停才停止 |
| 挂单未成交 | 回读 6×2s；超时撤单、暂停、不重复下单；启动前检查未完成委托 |
| 剩余资金 | 30%–70% 分级仓位、佣金预留、成交后 cashAfter 审计 |
| 数据复用 | ETF desk 8s 缓存 + single-flight；券商 status 8s 缓存；写后强制刷新 |
| 全局交易锁 | 自动/手动/清仓共用一把锁；单实例文件锁 |
| 每日基准 | 开盘权益不可变快照，防止重启重置 |
| 超仓减仓 | 持仓超过信号建议比例时按整手减仓 |
| 交易范围 | T+0 与量化共用交易接口/账户/持仓，顶部统一展示；各自显示策略范围 |
| 交易页 URL | `/jyt`；旧 `/etf` 自动跳转 |
| T+1 量化台 | 情绪锚浮现候选，人工确认/手工加入 T+1 池；自动引擎已接入，待实盘验证 |
| 交易页签 | T+0 交易 / 量化交易；账户持仓共用顶部模块 |
| 账户级持仓 | 全部持仓纳入总仓位；非池内持仓不忽略；全账户清仓 |
| 写操作确认 | orders + trades + portfolio 多源确认；不一致标记 unknown |
| 异步下单 | POST accepted 立即返回；后台 5s 核对，15s 未确认撤单 |
| ETF 实盘/自动（dry_run 联调） | 手动与自动均受 `mode=live`、确认、资金/持仓、单笔上限、止损、冷却保护；服务重启自动恢复；人工暂停保持暂停 |
| 数据源 | 公开接口，无 SLA；ST/北交所口径可能不同 |
| 用户体系 | 单用户 + 可选 APP_TOKEN，无多租户后台 |

## 四、可见入口冒烟

已实际验证：

- 决策台/全量监控切换
- 工具菜单四项均可打开
- 模拟买入、T+1 卖出拦截、重置
- 导入 JSON、导出的下载文件
- 预警规则、SSE 告警、Webhook 内网拦截
- 登录页、错误口令、正确口令会话
- 移动端工具菜单、视图切换

## 五、结论

功能数量已经足够。现在保留的每个模块都有：

1. 明确要回答的问题；
2. 能回到原始行情或规则；
3. 有可操作动作或可验证输出；
4. 有边界说明，不把派生值伪装成官方事实。

后续再增加功能前，应先回答：**它解决了哪个现有模块解决不了的问题？**
